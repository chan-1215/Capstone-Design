## 3. 하드웨어 이해와 번호 정정

처음에는 앞바퀴 회전을 모터로 독립 정지시키는 요청으로 이해했으나 사용자가
앞바퀴는 서보 조향, 추진은 후륜 두 DC 모터라는 점을 설명했습니다.
최종 정지 대상은 커브 안쪽의 후륜 모터입니다. 앞바퀴 한쪽을 독립 제동하는 기능은 없습니다.

| 채널 | 최종 코드의 좌우 정의 | BCM GPIO | 차량 전진 | 차량 후진 |
| --- | --- | --- | --- | --- |
| motor1 | 왼쪽 후륜 | `(20, 21)` | `forward()` | `backward()` |
| motor2 | 오른쪽 후륜 | `(23, 24)` | `backward()` | `forward()` |
| servo | 앞바퀴 조향 | `18` | 수동·자동 각도 변환 구분 | 수동 조향 사용 |

사용자의 최초 설명은 motor1=오른쪽이었으나 이후 motor2=오른쪽으로 정정했습니다.
현재 정의는 마지막 정정을 반영한 것이며 단품 물리 테스트로 독립 검증한 확정 배선표는 아닙니다.
핀 번호와 전진/후진 극성은 변경하지 않았습니다. 좌우 정지·증속의 논리적 대상만 바꿨습니다.

## 4. 전진 모터 제어 변경

기존 함수는 조향과 무관하게 두 모터를 항상 기본 보정 PWM으로 구동했습니다.
최종 함수는 조향 방향 인자를 받고 안쪽 모터를 정지시키며 바깥 모터에 증속을 적용합니다.

```python
apply_forward(motor1, motor2, speed,
              motor1_scale=1.0, motor2_scale=1.0,
              steering_angle=0.0)
```

수동 호출은 `steer` 입력을, 자동 호출은 계산된 논리 `angle`을 마지막 인자로 사용합니다.
수동 인자는 -1..1 범위이며 함수는 인자의 크기가 아니라 부호와 0 여부만 사용합니다.

| 입력 부호 | 의미 | motor1 / 왼쪽 | motor2 / 오른쪽 |
| --- | --- | --- | --- |
| 양수 | 오른쪽 커브 | 전진 PWM × 1.35 | `stop()` |
| 음수 | 왼쪽 커브 | `stop()` | 전진 PWM × 1.60 |
| 0 | 직진 | 전진 PWM × 1.10 | 기존 전진 PWM |

별도 조향 데드밴드는 없습니다. 자동 제어의 작은 양수/음수 각도도 커브 분기로 들어갑니다.
실제 자동 주행에서 이 영향은 아직 확인하지 않았습니다.
`stop()`은 역회전 능동 제동을 추가한 것이 아닙니다. 명령 정지와 물리적 즉시 정지는 구분해야 합니다.

## 5. 증속·보정 상수와 계산식

```python
RIGHT_TURN_LEFT_MOTOR_BOOST = 1.35
LEFT_TURN_RIGHT_MOTOR_BOOST = 1.60
STRAIGHT_LEFT_MOTOR_TRIM = 1.10
```

`v=speed`, `s1=motor1_scale`, `s2=motor2_scale` 기준 최종 계산:

```text
직진:        motor1 = min(1, v * s1 * 1.10), forward
             motor2 = min(1, v * s2), backward

오른쪽 커브: motor1 = min(1, v * s1 * 1.35), forward
             motor2 = 0, stop

왼쪽 커브:   motor1 = 0, stop
             motor2 = min(1, v * s2 * 1.60), backward

후진:        motor1 = v * s1, backward
             motor2 = v * s2, forward
```

전진 PWM에는 상한 1.0을 적용합니다. 후진 출력과 기존 인자 검증은 그대로입니다.
모터 2의 `backward()`가 차량 전진인 기존 극성을 유지했습니다.

속도 `0.22`, 보정값 `1.08 / 0.89`를 사용할 때:

| 동작 | motor1 PWM 크기 | motor2 PWM 크기 |
| --- | ---: | ---: |
| 직진 | 0.26136 | 0.19580 |
| 오른쪽 커브 | 0.32076 | 0 |
| 왼쪽 커브 | 0 | 0.31328 |
| 후진 | 0.23760 | 0.19580 |

커브 배율을 다르게 한 이유는 현재 보정값에서 두 방향의 활성 모터 PWM을 비슷하게
높이기 위해서입니다. 같은 PWM이 같은 실제 RPM을 보장하지 않습니다.
직진 10% 보정은 왼쪽 쏠림 보고에 대한 초기값이며 마지막 물리 결과는 아직 미확인입니다.

## 6. 수동 A/D 방향 보정

사용자는 A에서 오른쪽, D에서 왼쪽으로 간다고 보고했습니다.
이에 수동 경로의 서보 목표만 아래처럼 수정했습니다.

```python
# 기존 수동 호출
self.servo.angle = servo_target(self.servo_center, angle)

# 최종 수동 호출
self.servo.angle = servo_target(self.servo_center, -angle)
```

`servo_target()` 함수 자체와 자동 호출은 변경하지 않았습니다.
수동 서보 방향 변경은 후륜 모터 보정과 별개의 변경입니다.
초기에는 모터만 수정했지만 이후 사용자의 반대 방향 관찰에 따라 이 조향 수정이 추가되었습니다.
상태 응답의 `servo_target`도 수동 모드에서 실제 전달한 목표값과 일치하게 수정했습니다.
중심 0에서 모의 검증된 수동 A 목표는 -80도, D 목표는 +85도입니다.
이는 서보 명령각이며 실제 앞바퀴의 실측 조향각은 아닙니다.

이후 왼쪽 커브에서 양쪽 후륜이 돈다는 보고에 수동 모터 분기 기준도 바꿨습니다.

```python
self.motor_pwm_commands = apply_forward(
    self.motor1, self.motor2, self.forward_speed,
    self.motor1_scale, self.motor2_scale, steer)
```

이제 수동 좌우 모터 선택은 서보 각도·중심값이 아니라 A/D 방향 입력 기준입니다.
웹의 W/A/S/D 및 복합 입력 처리 코드는 수정하지 않았습니다.
A/D만 눌러 전진 입력이 0이면 두 구동 모터는 정지하고 조향만 합니다.

## 7. 명령 PWM 상태 추가

`DriveController`에 `motor_pwm_commands = (0.0, 0.0)`을 추가했습니다.
전진·후진 함수가 명령한 두 PWM을 반환하고 수동·자동 경로가 이를 저장합니다.
정지, 키 해제, 전진 입력 없음, 제어 중 정지 때 명령값을 0으로 초기화합니다.

새 `/status` JSON 필드:

```json
{
  "drive": {
    "motor1_pwm_command": 0.26136,
    "motor2_pwm_command": -0.1958
  }
}
```

부호는 GPIO Zero 객체 기준으로 양수 `forward()`, 음수 `backward()`, 0 `stop()`입니다.
모터 2의 배선 극성 때문에 차량 전진에도 음수가 표시됩니다.
이 값은 RPM·전류·엔코더·실제 회전 센서값이 아닙니다.
웹 UI 파일은 수정하지 않아 새 필드는 상태 JSON에서 확인합니다.

```python
MAX_CORNER_SECONDS = 0
```

기존 GitHub 및 보정 작업 사본의 값은 1.2초였습니다.
최종 Pi 값 0을 이번 저장 요청에 따라 그대로 보존했습니다.
이 값의 변경 주체·의도를 별도 검증하지 않았으며 검증된 개선으로 주장하지 않습니다.

자동 코너 시험 전에 의도와 정지 동작을 확인해야 합니다.

`Path.read_bytes()` + `cv2.imdecode()`로 처리했습니다. 저장된 카메라·영상 인식
코드나 Pi 런타임을 변경한 것이 아닙니다.

```bash
cd 'Auto Driving@'
python -m pip install -r requirements-pc.txt
python -B verify_pc.py
```

PC 요구 패키지는 회귀 테스트용입니다. Pi 구동용 GPIO Zero·CSI 카메라 프로그램·
선택적 MediaPipe·외부 KNN 모델이나 scikit-learn 학습 환경을 대신하지 않습니다.
테스트는 모의 GPIO·저장 이미지·임시 로컬 웹 서버를 사용하며 실제 바퀴를 구동하지 않습니다.
